# Start or resume a SilentDeluge Project

**Trigger:** “start working on Project XYZ for SilentDeluge.” The named GitHub Project and its linked repository issues are the queue. PLAN.md explains scope, not which card to pick next. Use the repository-bound `gh` from the SilentDeluge checkout. Never put private hostnames, real sightings, raw captures, credentials or private design URLs in issues, patches or prompts.

1. **Resolve.** Read PLAN.md and CONTEXT.md. Confirm `gh repo view --json nameWithOwner`; list `gh project list --owner OWNER --format json`. Match the exact project and linked repo, then `gh project item-list NUMBER --owner OWNER --format json --limit 200` (paginate if needed). Inspect open issues, PRs, branches and the last handoff comment on each active issue. If there is no board, record the blocker on the coordinating issue; do not claim the board exists. An owner-authorized session can `gh project create --owner OWNER --title TITLE`, `gh project link NUMBER --owner OWNER --repo OWNER/REPO`, then `gh project item-add NUMBER --owner OWNER --url ISSUE_URL` for each scoped issue. Reuse existing issues/items; don't duplicate them on restart.
2. **Slice.** Astra 6.2 owns roadmap, dependency ordering, contracts, integration, review and acceptance. Each implementation issue needs a user-visible result, input/output contract (including failure), file ownership, dependencies, non-goals, verification scenario and privacy constraints. Split issues when slices can be accepted separately. Separate code qualification, live acceptance and unattended authorization. Use the default Todo / In Progress / Done status; record blockers and dependencies by linked issue. A missing permission is a blocker, not another implementation task.
3. **Claim.** Check for an active claim/PR before dispatch. Record issue, worker/model, base commit, owned paths or worktree, and integration owner in the issue comment. Set status In Progress. GitHub assignees must be real authorized users, not fabricated agent identities. Models are recorded in the claim. A lost session does not invalidate a branch: recover the existing diff and evidence before assigning a replacement.
4. **Dispatch one wave.** Pin `openai-codex/gpt-6.2-sol` for implementation; verify availability with `omp models find gpt-6.2-sol`. Use an exact-model worker session (`omp -p --model openai-codex/gpt-6.2-sol '…'`) or a subagent explicitly mapped to that model. If unavailable, mark blocked; do not substitute. Give each worker its issue, shared contract, allowed files, non-goals and acceptance scenario. Run independent workers concurrently; isolate overlapping changes in separate worktrees. Workers edit their slice, never change project status, deploy, publish, enroll sources or choose a new architecture. They return files, proof available and unresolved risks. Keep credentials and live endpoints outside worker scope.
5. **Integrate.** Astra reviews the combined diff and exercises the public entrypoint with synthetic data: scope, provenance, partial/failure semantics, zero declarations and privacy. Run the narrow scenario for each changed provider, not just import checks. Return defects to the owning Sol worker. Document live evidence privately and cite only a sanitized result. An issue isn't accepted because a worker exited successfully.
6. **Publish and hand off.** Push the scoped feature branch and open/update a PR with issue references, test commands, observed results and remaining gates. Link the PR in each issue. Close implementation issues and set Done after landing verified changes on the target branch; keep unverified work open. At interruption, comment with base/branch, commit or draft PR, checks already run, blockers and the exact next action. Use GitHub for live state, repository Markdown for durable decisions and setup instructions.
